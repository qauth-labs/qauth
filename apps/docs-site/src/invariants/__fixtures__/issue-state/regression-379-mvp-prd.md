> 📌 **Status update (July 2026) — the T4 platform track has largely landed.** This document's phase breakdown treats Phases 4–5 as future work; that is no longer accurate. The **ADR-002 identifier-abstraction migration is complete** (epic #224, migrations 0010–0012), **post-quantum hybrid signing is implemented and default-off** (epic #241), and the **wallet-federation verifier stack is merged** — OID4VP transport, SD-JWT VC validation, key attestations, status-list revocation, claims normalization, account linking, `acr` propagation and the sign-in UI. A browser **can complete a wallet sign-in** behind `WALLET_FEDERATION_ENABLED` (off by default), covered end-to-end against a mock wallet by the #240 suite. Remaining T4 work is HAIP profile wiring (#377), key-storage assurance (#379) and the real-wallet interop pass (#376). (`WalletProvider.verify()` — the generic `CredentialProvider`-registry entry point — still throws by design; the wallet login path does not call it.) **This PRD is a planning record, not a live status surface** — for current status see the [README](./README.md#-current-status-july-2026) and the [docs index](./docs/README.md).
